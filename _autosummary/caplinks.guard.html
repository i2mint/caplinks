caplinks.guard#

The per-link lock-out: limit password tries, and lock a link that takes too many.

Two counts, because they defend against different things. Tries of one client on one link are limited so that a guesser locks out only itself; the wrong passwords a link takes from everyone are limited too, and past that the link’s unlock is closed for a while (a distributed guess). A host calls AttemptGuard.allow() before it checks a password and AttemptGuard.failed() after a wrong one.

>>> t = [0.0]
>>> guard = AttemptGuard(
...     client_limiter=SlidingWindowLimiter(max_per_window=5, clock=lambda: t[0]),
...     link_limiter=SlidingWindowLimiter(max_per_window=1, clock=lambda: t[0]),
...     lock_s=60, clock=lambda: t[0])
>>> guard.allow("link", "1.2.3.4")
True
>>> guard.failed("link"); guard.failed("link")  # the second one locks the link
>>> guard.allow("link", "5.6.7.8")
False
>>> t[0] = 61.0; guard.allow("link", "5.6.7.8")
True

Bases: object

Decide whether a password try may be made, and lock a link that is being guessed.

client_limiter counts every try of one client on one link; link_limiter counts the wrong passwords a link takes from everyone and, past its limit, locks the link for lock_s seconds. Both are anything with allow(key) -> bool (a Redis one shares the count between workers); the lock itself is per process. clock returns a monotonic time in seconds (tests pin it; the default limiters use it too). Keep lock_s at least the limiter’s window, or the first failure after a lock ends locks the link again at once.
